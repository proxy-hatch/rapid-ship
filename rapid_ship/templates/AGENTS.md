# Kit templates

`rapid-ship init` and `sync` render these files into projects. [kit.toml](kit.toml) lists the seeded paths, the new-project seeds, the executable files, the optional skills and the template variables; every other file is managed.

- `common/` holds files for every stack, laid out as in a project; `python/` and `agnostic/` add or override files per stack. The [project root guide skeleton](common/AGENTS.md) is one of them. `python/AGENTS.md` repeats it with the source and test rows, marks the two comment Rules that Ruff's `ERA001`, `TD002` and `TD003` carry `enforced by: check:lint`, and adds the `dead-code` Rule, which says how to mark that step's false positives. The agnostic stack has no `lint` step, so the common skeleton marks them `advisory`. `tests/test_kit_contents.py` holds the two guides equal otherwise.
- Managed files are copied byte for byte. Seeded files substitute `{{project_name}}`, `{{package}}`, `{{owner}}`, `{{repository}}` and `{{code_owner}}`, and a `__package__` directory becomes the package. An empty owner or repository renders as `<owner>` or `<repository>` and comments out its line; only TOML and CODEOWNERS templates may use them. The lock does not record `{{code_owner}}`: rendering derives it from the owner, as `@` and the owner, or empty, which leaves `code_owner = ""` unset in `project.toml`.
- A seeded settings file comments a key only where its name and value do not show its contract: the values or units it accepts, a default that is not obvious, or a constraint (Spec 1 section 4). [tests/test_kit_seed_keys.py](../../tests/test_kit_seed_keys.py) checks that each `project.toml` seed names every key devctl's loader accepts, and that the `exceptions.toml` seed's commented example names each of its keys, so a new key needs its seed line.
- This repository vendors the Kit. After changing a template, run `uv run rapid-ship sync --in-place` and commit the template with its vendored copy. Never edit the vendored copy itself: sync would record the edited file as this repository's own and stop updating it. The `vendored` check step runs `uv run --locked rapid-ship status --strict`, which fails until they match.
- ruff and mypy check the vendored copy in `tools/devctl/` and skip this directory, so devctl is checked once. Tests import the vendored copy.
- `tools/devctl/devctl/github/askpass.py` is listed under `executable` in `kit.toml`, because git runs it as `GIT_ASKPASS`; a template's own file mode does not reach the rendered file.
- [common/.claude/settings.json](common/.claude/settings.json) is the seeded Claude Code wiring: one `PreToolUse` entry whose matcher names each tool in devctl's `WIRED_TOOLS`, `Monitor` last, and runs `"$CLAUDE_PROJECT_DIR"/devctl hook claude pre-tool`. It sets no `timeout`, because the merge guard's 300-second budget relies on Claude Code's default of 600 seconds. `tests/test_kit_contents.py` holds it equal to the seed that `tests/devctl/test_devctl_doctor_wiring.py` accepts.
- [common/.agents/hooks.json](common/.agents/hooks.json) is the seeded agy wiring: one hook, `devctl`, whose `PreToolUse` matcher names each of agy's tools in devctl's `WIRED_TOOLS` and runs `"$(git rev-parse --show-toplevel)/devctl" hook agy pre-tool`, because the hook spike observed agy running in the folder that holds `hooks.json`. This is not a verified contract for T3: the launcher fails outside Git before reading the event, even when `workspacePaths` names the repository. The [outside-repository trial](../../docs/trials/2026-10-28-agy-hook-outside-repository.md) records the offline failure and pending live capture. Its `timeout` of 600 seconds leaves the merge guard its budget, because agy blocks a call whose hook it kills. `tests/test_kit_contents.py` holds it equal to the seed that `tests/devctl/test_devctl_doctor_wiring_agy.py` accepts.
- [common/.github/workflows/devctl-check.yml](common/.github/workflows/devctl-check.yml) and [common/.githooks/pre-commit](common/.githooks/pre-commit) are managed Kit files: the CI workflow whose job `devctl check` the ruleset requires, with one concurrency group for each push run (its commit) and one for each pull request (its ref), and the fast-tier pre-commit hook. This repository's copies are refreshed by sync, never edited.
- [common/README.md](common/README.md) and [common/ARCHITECTURE.md](common/ARCHITECTURE.md) are seeded skeletons whose only variable is `{{project_name}}`, because an empty `{{owner}}` or `{{repository}}` is a `KitError` outside TOML and CODEOWNERS. Map rule 8 checks that both exist, that the root guide links both and that their local links resolve, so a root guide skeleton keeps its README and Architecture rows.
- The Python starter Patterns are `new_project` seeds under [python/](python/): four `docs/patterns/python-*.md` files, each with its reference module in `src/__package__/` and its test in `tests/`. A new seed needs a `new_project` entry in `kit.toml`, or `init` never writes it. `tests/test_kit_starter_patterns.py` holds the four Pattern files to map rule 5, and the Python CODEOWNERS seed lists each one, commented out, right after `/.rapid-ship/`.
- Before GA, the documentation release (plan 7's PR 7.4), the Kit keeps no backward compatibility (Spec 1 section 3). A new check fails at once, even on files an existing project already owns, and `sync` never edits a seeded file to fit a new Kit version: the project fixes its own files.
- The Python seed's `pyproject.toml` sets what the `dead-code` step needs: vulture and deptry in the dev group, `[tool.vulture] paths` of `src` and `tests`, which keeps `tools/devctl` out of vulture's scan, and `[tool.deptry] extend_exclude`, which keeps it out of deptry's. Its `known_first_party` names the package under `src/`, which deptry would not count as the project's own, and Ruff's `external = ["V"]` keeps vulture's `# noqa` codes from RUF102. Its settings test reads `Settings.log_level`, which vulture would otherwise report as unused.
- Keep template paths clear of the root `.gitignore` patterns: hatch drops ignored paths from the wheel without a warning. `scripts/smoke_distribution.py` fails when the wheel lacks a template.
- Rendering skips `.venv`, `__pycache__`, `.DS_Store` and `.pyc` files, and here every path git does not keep. A template that is not yet added still renders unless git ignores it.
