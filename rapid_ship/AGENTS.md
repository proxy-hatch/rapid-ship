# rapid_ship package

This root-level directory is the importable `rapid_ship` package behind the `rapid-ship` command. [pyproject.toml](../pyproject.toml) defines wheel selection and the `rapid-ship` entry point. The [plan index](../docs/superpowers/plans/2026-10-14-kit-and-setup.md) fixes the modules that later plans add here.

- [cli.py](cli.py) parses arguments and runs `init`, `status`, `sync` and `app`. It exits 1 on a `KitRefusal` and 2 on a `KitError`; `sync --in-place` also exits 1 when a migration applies, after it prints each one with its diff. `app` also runs outside a work tree; inside one, it passes on the Apps that `.rapid-ship/project.toml` records. `app --import-key <role>` runs `app_import` instead of `github_app`. [__main__.py](__main__.py) and the entry point call the same `main`.
- [github_app.py](github_app.py) runs `rapid-ship app`. For each role it uses the App that `.rapid-ship/project.toml` records for the repository. Otherwise it uses an App of the repository's owner whose key the Keychain holds. `GET /apps/<slug>` with the owner's `gh` confirms a public App. GitHub answers 404 for any private App, even the owner's, so `GET /app` under a token that the item's key signs tells which account owns that App. One machine can hold a developer's own keys and their organisation's, so an App of another account is skipped. Unless another item holds the owner's App, an item whose key GitHub refuses, or that cannot sign a token, stops the command with exit 1 and prints no `[github]` lines. Only a role with neither gets a new App. It reads everything before it changes anything. It refuses a user's repository, with exit 1, unless `gh` is signed in as that user. On an organisation's repository it creates an App only when `gh`'s login is an active admin of the organisation; otherwise it exits 1, opens no browser and says to ask an admin or to use `--import-key`. A recorded App with no key on this machine stops the command with exit 1 and names `rapid-ship app --import-key <role>`. A key kept under plan 4's item name, `rapid-ship/<role>-app`, is re-stored under the new name, and the old item stays. The command prints each App's ID, slug and install URL.
- [app_import.py](app_import.py) runs `rapid-ship app --import-key {worker,reviewer}`. It stores a developer's own private key, read on stdin up to 64 KiB, for the role's App that `.rapid-ship/project.toml` records. First, `GET /app` under a token that the key signs must show that App's ID and slug. It stores nothing, and exits 1, when no App is recorded, the Keychain item exists, stdin is a terminal or holds no unencrypted RSA PEM private key, or GitHub refuses the token or shows another App. Once it stores the key, it tells the developer to delete the key file that GitHub downloaded.
- [app_flow.py](app_flow.py) calls GitHub as an App. It runs GitHub's manifest flow for one App, on a user's account or, at `https://github.com/organizations/<organisation>/settings/apps/new`, on an organisation's: a server on `127.0.0.1` posts the manifest, takes GitHub's one-time code and exchanges it for the App and its key. `app_of_key` signs a token with a key, with the claims of devctl's `app_jwt`, and reads the App's ID, slug and owner from `GET /app`.
- [app_keychain.py](app_keychain.py) keeps each key in the macOS Keychain with `security`, from stdin, in an item named `rapid-ship/<role>-app/<App ID>`. It lists a role's items from `security dump-keychain` without `-d`, which prints attributes only. It also holds `AppSetupError` and the process runner (EX-11).
- [kit](kit/AGENTS.md) holds the Kit commands: templates, lock, `init`, `status`, `sync` with its migrations, and their git calls.
- [templates](templates/AGENTS.md) holds the Kit's files: the template tree and `kit.toml`. The wheel ships it, and this repository vendors it.
- [files.py](files.py) writes files for the Kit. `atomic_replace` replaces a file atomically, `create_file` creates one and never overwrites it, and `safe_path` and `relative_parts` refuse a path that leaves the repository or passes through a symlink. Writers validate the path with `safe_path`, create the parent directory and own serialization.
- [skills](skills/AGENTS.md) holds the engineering skill used while working on this repository.

`rapid_ship` cannot import devctl, so `app_keychain.keychain_service` and `app_flow.APP_PERMISSIONS` repeat devctl's; a test in `tests/devctl/test_devctl_github_app.py` keeps them equal. `kit/migrations.py` repeats how devctl's `without_code` skips links in code, and `test_the_root_guide_migration_reads_links_as_map_rule_8_does` in `tests/test_kit_migrations.py` holds it to map rule 8's results. An import-linter contract in `pyproject.toml` keeps the order of imports: `github_app` and `app_import`, which do not import each other, then `app_flow`, then `app_keychain`.

Import modules directly; `__init__.py` is a marker, not an alternate interface. Keep resources under this package: `importlib.resources.files("rapid_ship")` is the lookup root in an installed wheel. After packaging changes, run the root checks and the [distribution smoke](../scripts/AGENTS.md).
