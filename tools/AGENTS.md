# Tools

[devctl/](devctl/) is this repository's vendored devctl, written by `uv run rapid-ship sync --in-place` from the templates in `rapid_ship/templates/common/tools/devctl/`. Never edit `devctl/devctl/` by hand: change the template, then sync. The `vendored` check step fails when the two differ. `devctl/devctl_project/` is seeded and owned here; it adds rapid-ship's own check steps: `vendored`, `distribution` and `python-3.12`. Their tests are in `tests/devctl/test_devctl_project_steps.py`, and `tests/devctl/test_devctl_project_dogfood.py` checks that they still run after a sync.

`devctl doctor` lives in `devctl/devctl/doctor*.py` and `harness.py`; `doctor --settings` is the quick read that skips GitHub, and its settings item is `settings_item` in `doctor_local.py`; Agent identity's token code is in `devctl/devctl/github/`, and `devctl as` in `identity.py`. Read `github/app.py` before any change that touches a token: a token reaches only one gh or git child and never a file, an argument or output.

`devctl hook` lives in `devctl/devctl/hook.py`, with the types and each wired Harness's protocol, Claude Code's and agy's, in `hook_protocols.py`, the shell, git and gh parsers in `command_line.py`, and the program each command runs, past wrappers such as `env` and git's global options, whose `-c` and `--config-env` values G1 reads, in `program.py`. The merge guard is in `merge_guard.py`, and its GitHub reads in `merge_guard_github.py`. In Flight it reads a PR's body with the `evidence` step's parsers and classes a declared removed test with the `diff` step's `is_unit_test`, so the guard and the steps read a body alike. `codeowners.py` holds the Protected-set reader that the hook, the guard and the `diff` step share, and `doctor_wiring.py` doctor's items for the Claude Code and agy wiring. The hook never exits 2, which Claude Code reads as block, and for agy it always exits 0 with a JSON answer, because agy blocks the call on any other exit code; a failure of devctl's own denies the agy call with the error as its reason. The agy seed runs `./devctl hook agy pre-tool` without shell expansion; managed `.agents/devctl` forwards by its own location to root `devctl`. Doctor rejects shell-dependent launch syntax and checks direct and shell invocation from root and `.agents/`, including missing or unusable launchers. These deterministic probes do not verify workspace trust or live ACP behavior. Existing projects update the seeded command manually; sync adds the managed forwarder. The relative seed supports only these two launch directories. Explicit tool `Cwd` outside Git still selects no repository: G7/G8 give no decision, while G1/G2, recognized G3 forms and the merge guard retain their decisions. Edits select the repository of their path; G5 remains omitted. The [trial](../docs/trials/2026-10-28-agy-hook-outside-repository.md) distinguishes successful wrapper `/bin/sh -c` probes from failed direct legacy-seed CLI launch and successful direct new-seed acceptance. These support a shell-syntax diagnosis; original raw subprocess argv and stderr are absent. Live ACP verification is quota-blocked, and the original ACP cause remains unverified. Change `WIRED_TOOLS` and the seeded matchers in `rapid_ship/templates/common/.claude/settings.json` and `rapid_ship/templates/common/.agents/hooks.json` together; the wiring tests fail when they differ.

The map rules are in `devctl/devctl/check/map.py`, except rule 7, which `check/map_skills.py` holds so `map.py` stays under the file-size cap; both read front matter through `check/markdown.py`. Every rule, and the references in `check/references.py`, reads only the files that git tracks, through `TrackedFiles` in `check/tracked.py`. The `diff` step in `check/diff.py` holds the diff cap, `counted_lines` and the ledger rule, and `check/evidence.py` reads the `Over the diff cap:` declaration.

The `dead-code` step for Python, its floor settings (`dead_code_gaps`) and the reader of the allowlist items in `pyproject.toml` (`toml_allowlist`) live in `check/stacks/python_dead_code.py`, outside `check/stacks/python.py`, which stays under the file-size cap. deptry's comment pattern is in `check/stacks/python.py` with the other comment rules. `tool_line_rules`, in `python_dead_code.py`, reads the first line of each node and import, and each name's own line in a plain `import`, as vulture and deptry read them, strings included. `check/exceptions.py` reads the allowlist items and those lines as suppressions. doctor's vulture and deptry exclusions are in `doctor_local.py`.

`settings.py` reads sorted `ProjectStack` entries from `[[stack]]` tables and resolves file ownership to the innermost directory. `jsonc.py` reads JSONC; `node.py` shares local Node tool lookup, ESLint configuration and install advice. Doctor checks each Python stack's floor and Protected settings under its directory. Check wraps mutable `StackStep` instances with `CheckContext.directory` and their result names; common and project steps run at the root. One root stack keeps plain names; other stacks use `lint (backend)`, or `lint (backend, python)` for a shared directory. `check/references.py` resolves against holder ownership, then a unique matching stack; ambiguity lists candidates and supported test/check alternatives. TypeScript steps, installation and doctor floors are implemented; init renders stacks under their directories. The lock reader accepts both forms until 6.3.

`check/stacks/typescript_suppressions.py` exposes pure TypeScript line rules and located knip JSONC allowlist items. `check/stacks/vitest.py` reads test identities and tautologies through the shared lexer in `vitest_tokens.py`. The exceptions step calls the TypeScript and knip readers for owned files. `check/stacks/typescript_references.py` validates tracked inputs before computing ESLint settings or tsc files, caching each tool per tracked snapshot and directory.

The diff and reference steps select the Vitest readers by test-file path. Evidence declarations and Rule references accept spaced identities inside backticks. The diff step notes dynamic base titles and retains base identities when head parsing fails.


`devctl/metrics/` is built in part: `settings.py` loads and validates `.rapid-ship/metrics.toml`, `model.py` defines the evaluation models and status logic, and `devctl metrics` CLI arrives in PR 3.4.

`devctl/devctl/check/stacks/typescript.py` runs each TypeScript tool from its stack directory. `check --install` prepends npm installation steps. `devctl/devctl/doctor_typescript.py` checks Node/npm and each TypeScript guardrail floor; `doctor_rules.py` places TypeScript Protected settings under each stack directory. Common Protected paths stay rooted at the repository.

`./devctl check` and `uv run pytest` need network access, gitleaks 8.30.1 on `PATH`, and Node.js 24.15.0 or later in major 24 with npm.
