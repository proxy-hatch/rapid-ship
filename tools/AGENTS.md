# Tools

[devctl/](devctl/) is this repository's vendored devctl, written by `uv run rapid-ship sync --in-place` from the templates in `rapid_ship/templates/common/tools/devctl/`. Never edit `devctl/devctl/` by hand: change the template, then sync. The `vendored` check step fails when the two differ. `devctl/devctl_project/` is seeded and owned here; it adds rapid-ship's own check steps: `vendored`, `distribution` and `python-3.12`. Their tests are in `tests/devctl/test_devctl_project_steps.py`, and `tests/devctl/test_devctl_project_dogfood.py` checks that they still run after a sync.

`devctl doctor` lives in `devctl/devctl/doctor*.py` and `harness.py`; `doctor --settings` is the quick read that skips GitHub, and its settings item is `settings_item` in `doctor_local.py`, whose ok detail also says whether the hook asks before a Protected edit and names `[escalation] protected_edits` with its value; Agent identity's token code is in `devctl/devctl/github/`, and `devctl as` in `identity.py`. Read `github/app.py` before any change that touches a token: a token reaches only one gh or git child and never a file, an argument or output.

`devctl hook` lives in `devctl/devctl/hook.py`, with the types and each wired Harness's protocol, Claude Code's, agy's and Codex's, in `hook_protocols.py`, the shell, git and gh parsers in `command_line.py`, and the program each command runs, past wrappers such as `env` and git's global options, whose `-c` and `--config-env` values G1 reads, in `program.py`. The merge guard is in `merge_guard.py`, and its GitHub reads in `merge_guard_github.py`. It validates project settings from the PR base commit with `settings.parse_project`; settings and CODEOWNERS reads use the same validated `base.sha`; local settings supply only its fallback repository. If all base CODEOWNERS locations return 404, the guard uses the Kit's common Protected paths, four starter Patterns and every supported stack's `protected_settings`; existing base files remain authoritative. In Flight it reads a PR's body with the `evidence` step's parsers and classes a declared removed test with the `diff` step's `is_unit_test`, so the guard and the steps read a body alike. `codeowners.py` holds the Protected-set reader that the hook, the guard and the `diff` step share, and `doctor_wiring.py` doctor's items for the Claude Code, agy and Codex wiring. G5 asks only while `[escalation] protected_edits` is true: `read_settings` fills `HookSettings.protected_edits` from the work tree's `project.toml` and `decide` reads it, while `HookSettings.protected` still holds the Protected set whatever the key says. The merge guard reads none of it; it validates the base branch's file with `parse_project`, which accepts the key. The hook never exits 2, which Claude Code and Codex read as block, and for agy it always exits 0 with a JSON answer, because agy blocks the call on any other exit code; a failure of devctl's own denies the agy call with the error as its reason. The agy seed runs `./devctl hook agy pre-tool` without shell expansion; managed `.agents/devctl` forwards by its own location to root `devctl`. Doctor rejects shell-dependent launch syntax and checks direct and shell invocation from root and `.agents/`, including missing or unusable launchers. These deterministic probes do not verify workspace trust or live ACP behavior. Existing projects update the seeded command manually; sync adds the managed forwarder. The relative seed supports only these two launch directories. Explicit tool `Cwd` outside Git still selects no repository: G7/G8 give no decision, while G1/G2, recognized G3 forms and the merge guard retain their decisions. Edits select the repository of their path; G5 remains omitted. The [trial](../docs/trials/2026-10-28-agy-hook-outside-repository.md) distinguishes successful wrapper `/bin/sh -c` probes from failed direct legacy-seed CLI launch and successful direct new-seed acceptance. These support a shell-syntax diagnosis; original raw subprocess argv and stderr are absent. Live ACP verification is quota-blocked, and the original ACP cause remains unverified. Change `WIRED_TOOLS` and the seeded matchers in `rapid_ship/templates/common/.claude/settings.json`, `rapid_ship/templates/common/.agents/hooks.json` and `rapid_ship/templates/common/.codex/hooks.json` together; the wiring tests fail when they differ.

The map rules are in `devctl/devctl/check/map.py`, except rule 7, which `check/map_skills.py` holds so `map.py` stays under the file-size cap; both read front matter through `check/markdown.py`. Every rule, and the references in `check/references.py`, reads only the files that git tracks, through `TrackedFiles` in `check/tracked.py`. The `diff` step in `check/diff.py` holds the diff cap, `counted_lines` and the ledger rule, and `check/evidence.py` reads the `Over the diff cap:` declaration.

The `dead-code` step for Python, its floor settings (`dead_code_gaps`) and the reader of the allowlist items in `pyproject.toml` (`toml_allowlist`) live in `check/stacks/python_dead_code.py`, outside `check/stacks/python.py`, which stays under the file-size cap. deptry's comment pattern is in `check/stacks/python.py` with the other comment rules. `tool_line_rules`, in `python_dead_code.py`, reads the first line of each node and import, and each name's own line in a plain `import`, as vulture and deptry read them, strings included. `check/exceptions.py` reads the allowlist items and those lines as suppressions. doctor's vulture and deptry exclusions are in `doctor_local.py`.

`settings.py` reads sorted `ProjectStack` entries from `[[stack]]` tables and resolves file ownership to the innermost directory; its `Escalation` holds `every_pr` and `protected_edits`, which both default to true. `jsonc.py` reads JSONC; `node.py` shares local Node tool lookup, ESLint configuration and install advice. Doctor checks each Python stack's floor and Protected settings under its directory. Check wraps mutable `StackStep` instances with `CheckContext.directory` and their result names; common and project steps run at the root. One root stack keeps plain names; other stacks use `lint (backend)`, or `lint (backend, python)` for a shared directory. `check/references.py` resolves against holder ownership, then a unique matching stack; ambiguity lists candidates and supported test/check alternatives. TypeScript steps, installation and doctor floors are implemented; init renders stacks under their directories. The lock reader accepts both forms until 6.3.

`check/stacks/typescript_suppressions.py` exposes pure TypeScript line rules and located knip JSONC allowlist items. `check/stacks/vitest.py` reads test identities and tautologies through the shared lexer in `vitest_tokens.py`. The exceptions step calls the TypeScript and knip readers for owned files. `check/stacks/typescript_references.py` validates tracked inputs before computing ESLint settings or tsc files, caching each tool per tracked snapshot and directory.

The diff and reference steps select the Vitest readers by test-file path. Evidence declarations and Rule references accept spaced identities inside backticks. The diff step notes dynamic base titles and retains base identities when head parsing fails.


`devctl/devctl/ledger.py` parses frozen Correction entries and last-pass records. Map rule 9 lives in `check/map_ledger.py`; it checks tracked ledger files and resolves prevention references through `references.py`, with tracked-only path fallback. It validates cursor commits locally.

`devctl/devctl/metrics/` has Tasks 5 to 7 and 9 built locally, with final acceptance pending: `settings.py` validates `.rapid-ship/metrics.toml`, `model.py` evaluates Suggested thresholds, and `github.py` and `window.py` read GitHub and local history. `revisions.py` counts distinct reviewed heads. `reverts.py` counts a PR once, from a later commit's `This reverts commit <sha>` line, a later PR's `Reverts <owner>/<repo>#<n>` body line in `Window.merged`, or the content check in `partial_reverts.py`; it reads no GitHub endpoint. A PR is an unknown item when its merge commit has no parent in the clone, when the clone is partial and `git log -p` would fetch file contents, or when the content check found nothing before the PR's `COMPARISON_BUDGET` ran out. The budget counts units: a similarity check spends `CHECK_COST` and 10 for each character of its two texts, so that even a check of two empty texts has a cost, and the full ratio spends the product of their lengths too. A PR with a restored file or an undone section already found counts as usual. `partial_reverts.undoing` reads one `git log --raw` for the PR and the commits after it, and one `git log -p` for each file whose hunks it compares, with options and config keys that fix git's output whatever the user has set for them. The `GIT_DIFF_OPTS` environment variable still overrides `-U0`, and the repository's own `.git/info/attributes` and a committed `.gitattributes` still apply and can make git read a file as binary; no option disables `.git/info/attributes`. It compares lines with `difflib.SequenceMatcher` and `autojunk=False`, so that a ratio of 0.8 means the same at every hunk size, and it counts a file as restored only when its mode and object id both match. `red_merges.py` reads each merge's earliest push run and its first attempt. `command.py` registers `devctl metrics [--window <n>] [--json | --post]` and measures a table of rows, each a title and a zero-argument callable, so a later metric adds a row; `report.py` renders text, Markdown and version-1 JSON. Exit 0 means no breach, 1 means a breach, and 2 means a guided error. API allowance exhaustion produces unknown values; Reverts still finishes. `GitHubReader.exhausted` returns the latch only after its reset-time lookup ends, whether or not it read the time. Project-defined metrics follow the basic ones with population `repository`, settings sources first. `api.py` holds the types that `devctl_project.metrics()` imports. `project.py` runs each code metric on a daemon thread under a 60-second limit, with a reader scope that closes at the thread's deadline or when the metric returns or fails; a metric whose read the closed scope refuses is unknown with the timeout reason, and Python cannot stop the thread's own work. Its `_call` holds the one blind catch for project code, which `.rapid-ship/exceptions.toml` lists. `sources.py` counts issues by label and deployments by environment. A failed metric or source is unknown with its reason, and a broken `metrics()` exits 2 naming `devctl_project`. The seeded `devctl_project` has a `metrics()` stub that returns `[]`; this repository's own has none. Closed unmerged and Corrections remain deferred.

`--post`, in `post.py`, is devctl's only write to GitHub. `command.py` refuses it with exit 2 unless `GITHUB_ACTIONS` is `true` and `GH_TOKEN` is set, and `--post` and `--json` exclude each other. Before any measurement, `prepare_post` lists the open issues that `github-actions[bot]` opened, through a projection that omits their bodies. It takes the lowest-numbered one that starts with the marker, checking its login, marker and pull request flag itself, and reads that one body for the previous statuses. A failed lookup is a failed post, never a new issue. `post` appends the Markdown report to the job summary, replaces the issue's body or opens the issue, and comments on a changed status, or on a breached or unknown one in a new issue. It reads nothing from GitHub, and its JSON comment writes every `>` as a unicode escape so that no value can end the comment early. A breach exits 0 once posted. `gh_write` sends one JSON body on stdin and never retries, because a write that timed out may have happened. Its tests are `tests/devctl/test_devctl_metrics_post.py` and `tests/devctl/test_devctl_metrics_workflow.py`.

`devctl/devctl/check/stacks/typescript.py` runs each TypeScript tool from its stack directory. `check --install` prepends npm installation steps. `devctl/devctl/doctor_typescript.py` checks Node/npm and each TypeScript guardrail floor; `doctor_rules.py` places TypeScript Protected settings under each stack directory. Common Protected paths stay rooted at the repository.

`./devctl check` and `uv run pytest` need network access, gitleaks 8.30.1 on `PATH`, and Node.js 24.15.0 or later in major 24 with npm; the signature test in `tests/devctl/test_devctl_metrics_reverts.py` also needs `ssh-keygen` and git 2.34 or later.

Codex reads every written path from `apply_patch`, including both sides of a move. Each path is judged in its own repository. Internal failures use Claude Code’s exit-1 path; G5 is absent. Doctor probes only the current-worktree command and names the owner’s `/hooks` trust step, which it cannot verify.
